# Зашифрованный аудиофайл: Tecno → iPad

Подготовлено 4 октября 2026 года после подтверждения владельцем доверия к аккаунту iPad и его сохранения при повторном открытии Tecno. После выполнения сценария владелец сообщил: «успешно и слышно». Проверка аудиофайла на Tecno и воспроизведение на iPad подтверждены владельцем.

## Результат на устройствах

4 октября 2026 года в ответ на просьбу проверить успешный результат на Tecno и наличие звука на iPad получено подтверждение обоих результатов. Этап пройден: приложение отправило тестовый аудиофайл, проверило зашифрованное событие и файл с сервера, затем точную нативную расшифровку; Element X на iPad воспроизвёл полученный звук.

Это результат проверки владельца на реальных устройствах; агент самостоятельно ими не управлял. Подтверждён сценарий с синтетическим WAV в направлении Tecno → iPad. Запись голоса, обратная отправка аудио и воспроизведение внутри нашего приложения этим тестом не проверялись.

## Проверка на устройствах

1. Компьютер с Metro и Tecno должны оставаться в одной локальной сети. В установленном development client на Tecno выполни Reload и дождись автоматического входа.
2. Во вкладке «Диагностика» нажми **«Отправить тестовый звук на iPad»**. Оставь Tecno открытым до результата. Приложение создаст один WAV-файл: два коротких сигнала, 1 секунда, 32 044 байта. Микрофон не используется. Кнопка перенесена сюда при подготовке следующего этапа записи голоса; инструкция для него — [MATRIX_VOICE_TEST.md](./MATRIX_VOICE_TEST.md).
3. Дождись **«Аудиофайл зашифрован и проверен»**. Этот результат означает проверку на Tecno, а не автоматическое подтверждение воспроизведения на iPad.
4. На iPad открой Element X, нашу комнату «Matrix · проверка двух аккаунтов» и последнее аудиосообщение `matrix-audio-….wav`. Включи его: должны прозвучать два сигнала.
5. Сообщи отдельно результат на Tecno и наличие звука на iPad. Если возникнет ошибка, передай её текст и последний этап. Пароли, токены и ключи передавать не нужно.

При отмене или истечении пяти минут файл мог уже попасть в очередь SDK или на сервер и прийти позже. Отмена ожидания отображается сразу; клиент остаётся занят до завершения нативной остановки. Приложение не создаёт повторную отправку автоматически. Сама очередь SDK может продолжать доставку ранее принятого файла. До повторного нажатия проверь комнату на iPad.

Повторное сравнение эмодзи перенесено в «Диагностику». Кнопка чтения статуса доверия остаётся во вкладке «Устройства».

## Условия успеха в коде

- Используется сохранённая комната и существующая сессия Tecno. Сервер должен показать только два вступивших аккаунта; проверяются шифрование комнаты, готовность нативной настройки и список участников. В SDK должны быть подтверждены сессия Tecno, собственная identity и identity аккаунта iPad, без нарушения прежнего доверия.
- `Timeline.sendAudio` получает синтетический PCM WAV через `UploadSource.Data`. `AudioInfo` содержит MIME `audio/wav`, размер `bigint` и длительность 1000 мс. JavaScript не реализует шифрование вложения: это делает SDK.
- Завершение `SendAttachmentJoinHandle.join()` не считается доказательством доставки. Нужен удалённый элемент timeline с origin `Sync`, настоящим event ID, нашим отправителем, типом Audio и уникальным именем текущего теста. Локальные и кэшированные события исключаются.
- По event ID запрашивается исходное серверное событие: проверяются `m.room.encrypted`, Megolm, идентификаторы и отсутствие открытого имени файла в содержимом.
- Из `MediaSource.toJson()` проверяется описание `file` версии v2 с ключом A256CTR, IV и SHA-256. В результат попадает только безопасная проекция; ключ и исходный JSON не выводятся и не сохраняются в отчёте.
- Первый `Client.getMediaFile` использует Plain `MediaSource.fromUrl` для того же MXC и `useCache=false`. Проверяются размер, отличие от открытого WAV и совпадение SHA-256 скачанного шифротекста с описанием вложения.
- Второй вызов получает исходный Encrypted MediaSource и снова `useCache=false`. Rust SDK скачивает и расшифровывает файл. Все байты должны совпасть с исходным WAV.
- Временные файлы читаются через Expo FileSystem и освобождаются через `MediaFileHandle.uniffiDestroy()`. Перед чтением в JavaScript проверяется ожидаемый размер. Это ограничение чтения в JS, а не общий лимит сетевого скачивания в нативном SDK.
- Сырые нативные ошибки не показываются: они могут содержать описание файла с ключом. Показываются фиксированное сообщение и последний этап. Ошибки очереди отправки также завершают тест без ложного успеха.

Важная особенность Rust SDK 0.18.0: `get_media_file` при `filename=None` игнорирует `temp_dir` и использует системный временный каталог. Поэтому передаём собственное безопасное имя `.wav` и путь `Paths.cache`; это выбирает `TempDir::new_in` в доступном приложению каталоге. Пользовательские пути и имена из чужих сообщений не используются.

## Проверенные источники

- Установленные сгенерированные API `@unomed/react-native-matrix-sdk` 0.10.2: `AudioInfo`, `MessageType.Audio`, `UploadSource.Data`, `Timeline.sendAudio`, `SendAttachmentJoinHandle`, `Client.getMediaFile`, `Client.subscribeToSendQueueStatus`.
- [FFI timeline на SHA 1c44fb6](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/bindings/matrix-sdk-ffi/src/timeline/mod.rs): отправка аудио и `use_send_queue()`.
- [FFI MediaSource](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/bindings/matrix-sdk-ffi/src/ruma.rs): сериализация JSON и создание Plain из MXC.
- [Медиа в Rust SDK](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/crates/matrix-sdk/src/media.rs): обход кэша, расшифровка, временный каталог и время жизни файла.
- [Cargo.lock](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/Cargo.lock) фиксирует ruma-events 0.34.0; [формат MediaSource этой версии](https://github.com/ruma/ruma/blob/ruma-events-0.34.0/crates/ruma-events/src/room.rs).
- [ClientBuilder](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/crates/matrix-sdk/src/client/builder/mod.rs): очередь отправки включена по умолчанию.
- [Expo FileSystem 57](https://docs.expo.dev/versions/v57.0.0/sdk/filesystem/), [Expo Crypto 57](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/). Длительность UniFFI проверена по установленному `ffi-converters.ts`: миллисекунды в TypeScript, секунды и наносекунды в Rust.

## Локальные проверки и границы

TypeScript и lint прошли. Все 120 прежних тестов и 27 новых аудиотестов прошли. Новые тесты проверяют WAV, фильтрацию событий, шифротекст и расшифрованные байты на независимых Node AES-CTR фикстурах, доверие, ошибки, отмену, отсутствие секретов в результате и освобождение временных файлов. Это модели нативных вызовов, не запуск Rust на устройстве.

Android-экспорт с Hermes прошёл. Зависимости и нативная конфигурация не менялись; новая EAS-сборка не запускалась, нужен Reload существующего APK. Expo Doctor ранее прошёл 21/21; на этом этапе без изменения зависимостей повторно не запускался.

Этот этап проверяет отправку одного синтетического файла. Запись голоса, воспроизведение внутри нашего приложения, получение голосовых с iPad, история вложений после перезапуска, фоновая доставка, перенос ключей и восстановление не реализованы этим изменением. Подтверждение аккаунта iPad не означает подтверждение всех его устройств или обратного доверия на iPad.
