# Проверка шифрования одного тестового сообщения

4 октября 2026 пользователь подтвердил на Tecno результат «Шифрование и расшифровка подтверждены». Это относится к тесту собственного сообщения в одной сессии. Сохранение входа после перезапуска добавлено следующим этапом и ещё требует проверки устройства.

## Как запустить

1. Для версии с сохранением входа установите обновлённый APK, выполните Reload и нажмите «Войти в Matrix». Войдите в тестовый аккаунт один раз.
2. На экране «Связь с Matrix» нажмите «Проверить шифрование сообщения».
3. Дождитесь результата. Лимит ожидания — три минуты; проверку можно отменить. При уходе приложения в фон она отменяется.
4. Успешный результат: «Шифрование и расшифровка подтверждены», исходный тестовый текст, ID комнаты/события, тип `m.room.encrypted` и алгоритм `m.megolm.v1.aes-sha2`.
5. После проверки нажмите «Выйти из аккаунта».

Кнопка создаёт отдельную закрытую комнату с шифрованием, без приглашений. Повтор в этой же сессии использует ту же комнату. Старый тест без шифрования остаётся доступен отдельной кнопкой. Комнаты и тестовые сообщения остаются на сервере.

Сам тест шифрования был проверен в первоначальном APK. Для следующего этапа с SecureStore требуется обновлённый APK. Код открывается через Metro `http://192.168.100.5:8081`.

## Условия успешного результата

Проверка проходит только при выполнении всех условий:

- SDK создаёт комнату с `isEncrypted: true`. До отправки отдельный HTTPS GET читает `m.room.encryption` на сервере и проверяет алгоритм Megolm. Затем `Room.latestEncryptionState()` должен вернуть `Encrypted`: приложение до 20 секунд ждёт актуального состояния SDK через sync. `Unknown` не считается ни включённым, ни выключенным шифрованием.
- `Room.sendRaw('m.room.message', ...)` шифрует сообщение в Rust и отправляет его.
- SDK получает событие через sync и выдаёт исходный тестовый текст после расшифровки. Проверяются `isRemote`, `EventItemOrigin.Sync`, ID события, отправитель и точное совпадение уникального тела пробы. Локальное событие, кэш, пагинация и событие без подтверждённого происхождения не засчитываются.
- Отдельный HTTPS GET `/_matrix/client/v3/rooms/{roomId}/event/{eventId}` читает это же событие с сервера. Проверяются ID/отправитель/комната, `m.room.encrypted`, алгоритм Megolm, непустые `ciphertext` и `session_id`, отсутствие открытых `body`/`msgtype` и исходного текста в содержимом.

Шифрование, получение и расшифровку выполняет **нативный Matrix SDK**. Дополнительные GET выполняются через JavaScript `fetch` и проверяют серверную настройку комнаты и формат события. Они не заменяют нативную отправку или синхронизацию. Для запросов используется текущий access token из `Client.session()` в заголовке Authorization. Начиная с этапа сохранения входа токен хранится в SecureStore; на экран и в журналы он не выводится. В UI возвращаются только тип события, алгоритм и длина шифротекста, без самого шифротекста, ключей и сырого ответа.

`LazyTimelineItemProvider.latestJson()` не используется как доказательство серверного шифротекста: timeline может уже содержать расшифрованный JSON. Одного флага зашифрованной комнаты также недостаточно.

Если SDK получил сообщение, а дополнительное чтение с сервера не удалось, экран сообщает, что проверка шифрования не завершена. Успех не показывается. При отмене сообщение могло уже попасть на сервер; автоматического повтора нет.

## Границы этого теста

Это проверка шифрования собственного сообщения в одной сессии и на одном устройстве. Она не проверяет обмен между двумя телефонами, выдачу ключей другому аккаунту, доверие устройствам, cross-signing, резервную копию и восстановление.

Начиная с этапа сохранения входа, авторизованный SDK использует `SqliteStoreBuilder.passphrase()` в отдельном постоянном каталоге сессии. Токены и случайная passphrase сохраняются в SecureStore. После перезапуска восстанавливаются тот же device ID, хранилище и тестовые комнаты. Полное чтение истории после перезапуска ещё не проверено; используйте только тестовый текст. Автоматическое создание резервной копии и cross-signing отключены.

## Проверка исходников и кода

Проверены объявления API установленной библиотеки `@unomed/react-native-matrix-sdk@0.10.2` и исходники Rust SDK на SHA `1c44fb6`, который вернул установленный APK на Tecno:

- [FFI Room.sendRaw](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/bindings/matrix-sdk-ffi/src/room/mod.rs) вызывает нативную отправку.
- [Нативная отправка](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/crates/matrix-sdk/src/room/futures.rs) проверяет состояние комнаты, запускает `encrypt_room_event_raw()` и меняет сетевой тип события на `m.room.encrypted`.
- [RoomListService](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/crates/matrix-sdk-ui/src/room_list_service/mod.rs) включает `m.room.encryption` в required state для подписки.
- [Timeline FFI](https://github.com/matrix-org/matrix-rust-sdk/blob/1c44fb6/bindings/matrix-sdk-ffi/src/timeline/mod.rs) показывает различие локального/удалённого события и его происхождение.
- [Matrix Client-Server API](https://spec.matrix.org/latest/client-server-api/) описывает события шифрования и чтение события комнаты.

Автоматические проверки: TypeScript, lint, `node tests/matrix-network.test.mjs` и Android export. Тесты проверяют получение через sync, отличие локального события, соответствие пробы, отклонение открытого текста и чужого события, алгоритм и шифротекст, скрытие секретов. Они не заменяют запуск SDK на телефоне.

Результаты 4 октября 2026: TypeScript и lint пройдены; тесты — 9/9; Android export с Hermes завершён успешно. Metro отвечает `packager-status:running`. Зависимости не менялись, новая EAS-сборка не запускалась. Проверка шифрования на Tecno и проверка удобства формы с клавиатурой остаются за устройством.

## Исправление первой попытки

Пользователь сообщил ошибку «Режим шифрования комнаты не соответствует тесту» до отправки сообщения. Проверка была слишком грубой: `awaitRoomRemoteEcho()` может вернуть частично синхронизированную комнату, а FFI-метод `isEncrypted()` сводит ошибку `latest_encryption_state()` к `false`. Ошибка не доказывала отсутствие шифрования на сервере.

Проверка заменена на чтение настройки сервера и ожидание точного состояния `latestEncryptionState()`. Ошибки нативного чтения больше не подменяются значением `false`. При отсутствии серверной настройки, другом алгоритме, отмене или тайм-ауте сообщение не отправляется. Причина первой ошибки на конкретном устройстве требует повторного теста; отсутствие настройки на сервере теперь будет видно отдельно от задержки SDK.

Добавлены тесты частичной синхронизации (`Unknown → NotEncrypted → Encrypted`), запрета считать `Unknown` выключенным шифрованием, тайм-аута, отмены нативного чтения и сохранения ошибки чтения. Всего тестов — 15. После исправления необходимо выполнить Reload и войти снова, чтобы Fast Refresh не оставил старый объект сессии.

После исправления TypeScript, lint, все 15 тестов и Android export с Hermes прошли. Metro работает. Новая APK-сборка не нужна. Успешное шифрование на телефоне пока не подтверждено.
