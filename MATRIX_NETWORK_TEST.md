# Следующий этап: нативный SDK и Matrix-сервер

Этот экран подготовлен после успешной локальной проверки SDK на Tecno. 3 октября 2026 пользователь подтвердил отправку и получение собственного сообщения через нативный SDK. 4 октября подтверждены шифрование и расшифровка. ID события и время в чат не передавались. Обмен между двумя устройствами пока не проверен. Следующий этап — сохранение входа на одном телефоне.

## Как открыть

Для версии с сохранением входа требуется обновлённый APK с SecureStore. В development client откройте текущий проект через Metro и нажмите на первом экране кнопку «Войти в Matrix».

Адрес Metro в текущей локальной сети: `http://192.168.100.5:8081`. Компьютер и Tecno должны быть в одной сети. Если сервер остановился:

```powershell
$env:REACT_NATIVE_PACKAGER_HOSTNAME = '192.168.100.5'
npx expo start --dev-client --lan --port 8081
```

## Что нажимать

1. Пока аккаунта нет, нажмите «Проверить связь без аккаунта». Это реальный сетевой вызов нативного SDK. Успешный результат показывает ответ сервера и объявленную им поддержку входа и синхронизации.
2. Создайте отдельный тестовый аккаунт через https://account.matrix.org/register, используя регистрацию с паролем. При необходимости подтвердите адрес электронной почты. Пароль не отправляйте в чат.
3. Вернитесь в приложение. Для matrix.org оставьте адрес `https://matrix-client.matrix.org` и введите полный ID `@имя:matrix.org` и пароль на телефоне. Нажмите «Войти в тестовый аккаунт».
4. После входа нажмите «Отправить и получить тестовое сообщение». Кнопка создаёт закрытую комнату без приглашений. Комната и тестовое сообщение остаются на сервере. Повтор в этой же сессии использует ту же комнату.
5. Успех — «Сообщение отправлено и получено с сервера», текст пробы, ID комнаты и ID события. После проверки нажмите «Выйти из аккаунта», чтобы завершить серверную сессию.

Кнопка «Отправить и получить тестовое сообщение» проверяет получение собственного сообщения через синхронизацию этой же сессии. Комната для этой пробы **без шифрования**. Отдельная кнопка «Проверить шифрование сообщения» описана в [MATRIX_ENCRYPTION_TEST.md](./MATRIX_ENCRYPTION_TEST.md). Обмен между двумя устройствами, полный чат, дневник и восстановление пока не реализованы.

Для формы входа включена компенсация клавиатуры на Android и iOS с учётом высоты заголовка. При открытии клавиатуры и смене фокуса экран прокручивается к выбранному полю с отступом. «Далее» переводит фокус к следующему полю; «Готово» в поле пароля запускает вход. При запуске проверки клавиатура закрывается. Изменение доступно через Metro, новый APK не требуется; удобство ввода на Tecno после изменения ещё нужно подтвердить.

## Что делает код

- SDK загружается только при запуске проверки; веб-экран возвращает понятную ошибку вместо имитации нативного вызова.
- `ClientBuilder.inMemoryStore()`, `homeserverUrl()`, `slidingSyncVersionBuilder(DiscoverNative)` и `build()` создают временный клиент.
- `homeserverLoginDetails()` проверяет объявленные сервером способы входа и native sliding sync.
- `Client.login()` выполняет вход по паролю. ID пользователя читается после завершения входа.
- `syncService().withRoomListTimelineLimit(20).finish()` и `start()` запускают получение событий.
- `Client.createRoom()` создаёт приватную комнату. `roomListService().subscribeToRooms()` подписывается на неё; `awaitRoomRemoteEcho()` ожидает её появления с сервера.
- `Room.timeline().addListener()` слушает события; `Room.sendRaw('m.room.message', ...)` отправляет тестовый текст.
- Успех требует `EventTimelineItem.isRemote === true`, `EventId`, совпадения отправителя, типа текста и уникального тела пробы. Локальное отображение отправляемого сообщения и завершение HTTP-отправки сами по себе успехом не считаются.
- После пробы слушатели отменяются, sync останавливается, обёртки UniFFI освобождаются. Есть отмена, лимит ожидания и остановка проверки при уходе приложения в фон.

Теперь вход сохраняется на этом телефоне: токены и случайная passphrase — в SecureStore, данные и ключи SDK — в постоянном SQLite-хранилище с passphrase. Сам пароль не сохраняется и очищается после попытки входа. При повторном открытии экрана восстанавливается тот же device ID. «Выйти» отзывает сессию на сервере, удаляет сохранённый вход и локальные файлы. При ошибке восстановления можно повторить его или забыть вход локально; локальное удаление не отзывает серверную сессию. Пароль и токены не выводятся в журналы приложения.

## Проверки

Для этого этапа используются:

```powershell
npm run typecheck
npm run lint
npx expo-doctor
node tests/matrix-network.test.mjs
npx expo export --platform android --output-dir .expo/network-check
```

Пять автоматических тестов проверяют отличие локального события от события с сервера, обработку замены и начального снимка timeline, совпадение пробы, валидацию HTTPS-адреса, скрытие секретов и текст отмены. Они не заменяют сетевую проверку SDK на телефоне.

Результаты 3 октября 2026: TypeScript и lint пройдены; Expo Doctor — 21/21; автоматические тесты — 5/5; Android export с Hermes завершён успешно. Metro отдаёт HTTP 200 и Android-манифест `watcher-matrix-check` по адресу `192.168.100.5:8081`. Новых зависимостей не установлено, новая EAS-сборка не запускалась.

3 октября 2026 с компьютера проверены открытые HTTP-ответы matrix.org: discovery указывает на `https://matrix-client.matrix.org`; `/login` объявляет `m.login.password`; `/versions` объявляет `org.matrix.simplified_msc3575: true`. Это предварительная проверка сервера, а не подтверждение нативного входа на Tecno.

При ошибке сохраните этап и текст ошибки с экрана, без пароля. При отмене или тайм-ауте сообщение могло уже попасть на сервер; автоматического повтора нет.

Источники: [регистрация Matrix](https://account.matrix.org/register), [Matrix Client-Server API](https://spec.matrix.org/latest/client-server-api/), установленные исходники и объявления типов `@unomed/react-native-matrix-sdk@0.10.2`, [Expo Router 57](https://docs.expo.dev/versions/v57.0.0/sdk/router/).
