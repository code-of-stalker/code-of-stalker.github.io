# Проверка зашифрованного обмена между двумя аккаунтами

Сценарий подготовлен 4 октября 2026 года после подтверждения владельцем чтения старого зашифрованного сообщения на Tecno после полной остановки Android. Он соединяет наш Android-прототип и второй Matrix-аккаунт в Element X на устройстве Apple. Владелец подтвердил успешное прохождение сценария: «всё успешно прошло».

## Результат на устройствах

4 октября 2026 года после инструкции создать отдельный второй аккаунт и выполнить сценарий владелец сообщил об успехе. Подтверждены приглашение в тестовую комнату, получение запроса в Element X и получение точного зашифрованного ответа на Tecno. Условия успеха кода требуют расшифровки ответа нативным SDK и проверки серверного шифротекста обоих событий.

Это результат владельца на реальных устройствах; агент самостоятельно устройствами не управлял. Какое из устройств Apple использовалось — iPhone или iPad — не уточнялось. Наше приложение на iOS и доверие устройств не проверены. Чтение ответа второго аккаунта после полной остановки Tecno отдельно подтверждено владельцем в сценарии ниже.

## Подготовка второго аккаунта

1. Создайте другой тестовый аккаунт на [matrix.org](https://account.matrix.org/register). При необходимости подтвердите почту. Пароль вводите только на своих устройствах.
2. Установите [Element X из App Store](https://apps.apple.com/app/id1631335820) на iPhone или iPad и войдите во второй аккаунт. Первый аккаунт остаётся в прототипе на Tecno.
3. В Element X найдите полный адрес второго аккаунта, например `@второе_имя:matrix.org`. Вход в прежний аккаунт на другом устройстве не проверяет обмен между двумя пользователями.

Второй участник использует готовый Matrix-клиент. Наш прототип на iOS этим не запускается и не проверяется.

## Проверка на устройствах

1. На Tecno выполните Reload в установленном development client и дождитесь автоматического входа. Новый APK для этой проверки не требуется; компьютер и Tecno должны быть в одной локальной сети.
2. На экране «Связь с Matrix» найдите раздел «Обмен со вторым аккаунтом». Введите полный адрес второго аккаунта и нажмите «Создать комнату и пригласить».
3. В Element X на iPhone или iPad примите приглашение в комнату «Matrix · проверка двух аккаунтов».
4. На Tecno нажмите «Отправить тест и дождаться ответа». SDK проверит вступление второго аккаунта и шифрование комнаты, затем отправит один запрос. Держите оба приложения открытыми; ожидание ограничено пятью минутами.
5. В Element X откройте полученное сообщение. Скопируйте только последнюю строку вида `Matrix ответ …` и отправьте её отдельным обычным текстовым сообщением в эту же комнату. Не используйте цитату, реакцию или дополнительные слова.
6. На Tecno ожидается «Зашифрованный обмен подтверждён», адрес второго аккаунта и полученная строка ответа. В результате показываются идентификаторы комнаты, запроса и ответа.

При повторе создаётся новый случайный код запроса. Если ожидание отменено или истекло, автоматического повторного сообщения нет. После ухода Android-приложения в фон ожидание отменяется; для новой попытки нажмите кнопку отправки снова и отвечайте на новый запрос.

Если второй аккаунт ещё не вступил, сообщение не отправляется: приложение предлагает принять приглашение. Если ответ не появился или сообщение в Element X не расшифровывается, проверка не пройдена. Сохранённый вход удалять не нужно. Текст ошибки на Tecno или состояние сообщения в Element X нужны для дальнейшей диагностики; секреты и ключи присылать не следует.

## Что проверяет прототип

Создаётся отдельная закрытая комната с `isEncrypted: true` и приглашением указанного аккаунта через фактический API `Client.createRoom()` из `@unomed/react-native-matrix-sdk` 0.10.2. Она сохраняется в существующей защищённой записи как `peerRoom`. Повтор подготовки для того же аккаунта использует прежнюю комнату. Смена адресата создаёт новую тестовую комнату; предыдущая остаётся на сервере. Комнаты и контрольное событие проверки перезапуска сохраняются отдельно.

Перед отправкой HTTP GET `joined_members` должен подтвердить только два вступивших аккаунта: свой и выбранный второй. Состояние `m.room.encryption` на сервере должно использовать Megolm; нативный SDK также должен получить состояние `Encrypted`. `Timeline.fetchMembers()` загружает участников перед выбором устройств для передачи ключей. Политика SDK для распространения ключей не переопределяется.

`expo-crypto.getRandomBytesAsync(16)` создаёт случайный код текущего теста. `Room.sendRaw('m.room.message', ...)` отправляет запрос через нативный SDK. Слушатель timeline установлен перед отправкой. Успех требует нативных расшифрованных текстовых событий с `isRemote`, `EventId` и `EventItemOrigin.Sync`: запрос от своего аккаунта и точный ответ с этим кодом от выбранного второго аккаунта. Собственное сообщение, старый ответ, кэш, открытая локальная копия или ответ другого пользователя не засчитываются.

Для обоих идентификаторов событий отдельный HTTP GET проверяет серверное представление `m.room.encrypted`, алгоритм Megolm, наличие шифротекста и отсутствие открытого тестового текста. Токены, ключи, сырой JSON событий и шифротекст не выводятся в интерфейс. Слушатели отменяются, sync останавливается с отдельным сроком ожидания, обёртки SDK освобождаются.

Чтение запроса в Element X подтверждается вручную владельцем и отправкой точной строки из расшифрованного текста. Прототип программно проверяет получение и расшифровку ответа на Tecno. Это проверка обмена с другим клиентом, а не доказательство работы нашей iOS-сборки, проверки доверия устройств или восстановления ключей на другом телефоне.

## Прежний ответ после полной остановки Tecno

Сценарий подготовлен 04.10.2026 после подтверждения владельцем обмена между двумя аккаунтами. **Успех на Tecno подтверждён владельцем: «успешно».** Ответ получен после инструкции повторить обмен, закрыть Element X, полностью остановить прототип через настройки Android, снова открыть его с автовходом и нажать «Прочитать ответ после перезапуска».

Подтверждено чтение прежнего ответа другого участника с сохранённой сессией и ключами на Tecno. Условия успеха кода требуют того же события, отправителя и устройства, совпавшей контрольной суммы реально расшифрованного текста и серверного шифротекста. Агент самостоятельно устройствами не управлял; выполнение ручной полной остановки сообщено владельцем, а не установлено автоматической проверкой процесса Android.

### Проверка на устройствах

1. Выполните Reload на Tecno и дождитесь автовхода. Новый APK не нужен. Компьютер с Metro и Tecno должны оставаться в одной сети.
2. Повторите «Отправить тест и дождаться ответа» в уже созданной комнате. В Element X со вторым аккаунтом отправьте точную новую строку «Matrix ответ …». Повтор нужен один раз: до этого обновления приложение не сохраняло контрольное событие чужого ответа.
3. После успеха на Tecno в разделе «Ответ после перезапуска Tecno» появится запомненное событие. Полностью закройте Element X на втором устройстве.
4. На Tecno через настройки Android откройте сведения о приложении и нажмите «Остановить». Не нажимайте «Выйти из аккаунта», не удаляйте приложение и не очищайте данные.
5. Откройте прототип снова, дождитесь автоматического входа и нажмите **«Прочитать ответ после перезапуска»**. Перед чтением не отправляйте новый тест: он заменил бы запомненное событие. Второму участнику больше отвечать не нужно.
6. Ожидается **«Ответ второго аккаунта расшифрован после перезапуска»** вверху экрана, прежняя строка ответа и совпавшая контрольная сумма. Ошибка или отмена не засчитываются как успех; сохранённый вход и ключи сохраняются для повторного чтения.

Кнопка чтения становится доступной после открытия сохранённого клиента. Сам код не доказывает, что Android-процесс был полностью остановлен: для проверки требуется выполнить шаг 4 вручную, а не ограничиться Reload или уходом в фон. Ожидание чтения ограничено двумя минутами.

### Условия подтверждения

- После подтверждённого обмена `peerReplyCheckpoint` сохраняет комнату, ID ответа, адрес отправителя, ID принимающего устройства Tecno, время и SHA-256. Текст ответа и пароль в эту защищённую запись не добавляются. Сохраняются прежние токены, идентификатор хранилища, его пароль шифрования и собственный контрольный тест.
- Сохранение ответа должно завершиться до показа успеха. Обновление токена сохраняет эту запись. Подготовка прежней комнаты её не меняет; смена комнаты или второго аккаунта удаляет только устаревший контрольный результат чужого ответа.
- Чтение использует прежний SQLite/crypto store и прежний ID устройства. Проверяются комната и отправитель. HTTP GET должен подтвердить то же серверное событие `m.room.encrypted` с Megolm.
- Общий читатель `read-checkpoint.native.ts` открывает timeline восстановленного клиента, очищает только кэш событий тестовой комнаты через `Room.clearEventCacheStorage()` и вызывает `Room.loadOrFetchEvent()` для точного ID. Получение новых сообщений через sync, отправка, создание комнаты, импорт ключей и загрузка backup этим читателем не запускаются.
- Нативный результат должен быть `MessageLike → RoomMessage → Text` от сохранённого второго аккаунта. ID события и устройства должны совпасть, SHA-256 реально расшифрованного текста должен совпасть с сохранённым. Нерасшифрованный `RoomEncrypted`, другое событие, чужой отправитель или иной текст вызывают ошибку. Дополнительно серверное представление проверяется на отсутствие открытого текста ответа.
- Эта же функция используется для ранее подтверждённого собственного сообщения. Ошибка чтения, отсутствие ключей или отмена не удаляют SQLite, сессию и контрольный результат.

Это проверка сохранения ключей на Tecno для сообщения другого пользователя. Доверие устройств, перенос ключей, восстановление после удаления данных и наше приложение на iOS остаются отдельными этапами.
