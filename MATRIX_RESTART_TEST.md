# Старое зашифрованное сообщение после перезапуска

Автовход, сохранение сессии и новый интерфейс подтверждены владельцем на Tecno: «всё как надо». Чтение сообщения, отправленного до полной остановки приложения, также подтверждено владельцем 04.10.2026.

04.10.2026 владелец подтвердил «успешно» после предложения повторить «Проверить шифрование сообщения» с исправлением сохранения. Затем после инструкции полностью остановить приложение через настройки Android, открыть снова, дождаться автовхода и нажать «Прочитать сообщение после перезапуска» владелец повторно ответил «успешно». Это подтверждение результата владельцем на устройстве; агент самостоятельно телефоном не управлял.

## Проверка на Tecno

1. Выполните Reload в development client, дождитесь автоматического входа.
2. Нажмите «Проверить шифрование сообщения» и дождитесь успеха. В разделе «Сообщение после перезапуска» появится запомненное событие и устройство.
3. В настройках Android откройте приложение и нажмите «Остановить». Не выходите из Matrix-аккаунта, не удаляйте приложение и не очищайте его данные.
4. Откройте development client и проект снова. После автовхода нажмите «Прочитать сообщение после перезапуска». Перед этим повторно отправлять зашифрованное сообщение не нужно: оно заменило бы контрольное событие.
5. Ожидается «Старое сообщение расшифровано», прежнее событие, устройство и текст. Проверка чтения не отправляет новое сообщение и не создаёт комнату.

Новый APK не требуется: все необходимые нативные модули есть в установленной второй сборке. Metro нужен для загрузки актуального JavaScript.

## Как устроена проверка

- После успешного зашифрованного теста в существующей защищённой записи сохраняется `encryptedCheckpoint`: room ID, event ID, device ID, время и SHA-256 тестового текста. Сам текст в эту запись не добавляется. Старые записи без checkpoint продолжают открываться.
- SDK обновляет токены через `SessionVault`, сохраняя checkpoint. При выходе или забывании удаляется вся сохранённая сессия вместе с ним.
- Чтение доступно после открытия нового нативного клиента с сохранённой записью. В клиенте, который только что отправил контрольное сообщение, оно заблокировано. Это условие не доказывает остановку процесса Android: Reload тоже может создать новый клиент; для проверки полного перезапуска нужен шаг 3.
- Проверяется тот же device ID, room ID и event ID. Отдельный HTTP GET проверяет серверное событие `m.room.encrypted` с Megolm; его сырой JSON, токены и шифротекст в интерфейс не передаются.
- `Room.timeline()` открывает подписку кэша для восстановленного клиента. Sync при чтении не запускается. `Room.clearEventCacheStorage()` очищает только кэш событий закрытой тестовой комнаты в памяти и SQLite. Это не удаляет state store, crypto store, ключи или сообщения на сервере.
- `Room.loadOrFetchEvent(eventId)` при пустом кэше загружает событие заново. Нативный SDK должен вернуть `TimelineEventLike.content()` с `MessageLike → RoomMessage → Text`. Состояние, удалённое сообщение, другой отправитель, другое событие или нерасшифрованный `RoomEncrypted` не считаются успехом.
- SHA-256 реально полученного текста сравнивается с прежней контрольной суммой. Успех показывается после проверки серверного шифротекста и сохранения обновлённой сессии. Новая комната или новое сообщение для этой проверки не создаются.
- При ошибке или отмене checkpoint и ключи сохраняются, чтобы можно было повторить чтение. Ожидание ограничено двумя минутами.

Проверка относится к одному телефону и одной сохранённой сессии. Несколько пользователей, доверие между устройствами, перенос ключей, backup и восстановление после удаления приложения не проверяются.

## Источники API

Сигнатуры сверены с установленным `@unomed/react-native-matrix-sdk` 0.10.2, `src/generated/matrix_sdk_ffi.ts`.

- [Room FFI, Rust SDK 0.18.0](https://github.com/matrix-org/matrix-rust-sdk/blob/matrix-sdk-0.18.0/bindings/matrix-sdk-ffi/src/room/mod.rs): `clear_event_cache_storage`, `load_or_fetch_event`.
- [Room в Rust SDK 0.18.0](https://github.com/matrix-org/matrix-rust-sdk/blob/matrix-sdk-0.18.0/crates/matrix-sdk/src/room/mod.rs): загрузка события и `try_decrypt_event`.
- [Expo Crypto 57](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/): `digestStringAsync(CryptoDigestAlgorithm.SHA256, text)`.

Проверка реализована для тестовых сообщений. Владелец подтвердил успешный результат сценария выше на Tecno: старое зашифрованное событие прочитано после перезапуска с сохранённой сессией и ключами. Перенос на другое устройство и восстановление после удаления данных этим не проверяются.

## Исправление сообщения о свободном месте, 04.10.2026

Владелец сообщил об ошибке после «Проверить шифрование сообщения» при 38 ГБ свободного места. Код скрывал любую ошибку сохранения за советом проверить место. Фактическую нативную причину на телефоне пока не получили.

Локально воспроизведена несовместимость: сохранение комнаты требовало идентификатор с `:domain`. В [Matrix v1.16, Room IDs](https://spec.matrix.org/v1.16/appendices/#room-ids) описаны также идентификаторы без домена, используемые комнатами версии 12. Тест с таким идентификатором падал до исправления и проходит после него. Новый и прежний форматы теперь принимаются при сохранении и восстановлении.

Ошибки формата данных и отказа SecureStore теперь различаются. Для защищённого хранилища показывается только разрешённый код ошибки; исходные сообщения, которые могут содержать секреты, не выводятся. Ошибка последнего сохранения больше не скрывается завершением более ранней записи. Тесты проверяют сохранение комнаты и контрольного события, обновление токена, сохранность предыдущей записи и отсутствие удаления ключей при ошибке.

После предложения выполнить Reload и повторить «Проверить шифрование сообщения» владелец ответил «успешно». Успешный зашифрованный тест после исправления подтверждён на Tecno. Затем владелец подтвердил успех чтения прежнего сообщения после полной остановки Android по шагам 3–5 выше. Выход из аккаунта, очистка данных и новый APK для этого исправления не нужны.
