# Голосовые сообщения: Tecno и iPad

Обновлено 5 октября 2026. После исправления отправки M4A владелец подтвердил воспроизведение записи на iPad: «Прослушать получилось, но теперь это отдельный файл». Голос на Tecno также слышен по предыдущему сообщению владельца; какой именно плеер Tecno использовался (предпрослушивание или копия с сервера), отдельно не уточнялось. Синтетический WAV Tecno → iPad подтверждён ранее («успешно и слышно»).

Пожелание на последующий этап: запись должна выглядеть и проигрываться как обычное голосовое сообщение прямо в чате — с кнопкой воспроизведения/паузы и длительностью, без открытия отдельного файла. Совместимость с Element X на iPad и шифрование должны сохраниться. Сейчас это требование зафиксировано; реализация отложена по просьбе владельца («потом»).

## Текущий этап: прослушивание сохранённых записей без интернета

05.10.2026 владелец подтвердил, что Tecno снова увидел сервер разработки автоматически, без ввода нового адреса. Перед этим на Компьютере обнаружены остановленный Metro и смена адреса Ethernet с 192.168.100.5 на 192.168.100.8. Metro запущен с явным домашним адресом, при наличии VPN-интерфейсов. Блокировка домашней сети самим VPN не установлена.

Добавлены зашифрованные копии уже открытых голосовых из общей истории: до 10 записей текущей комнаты. Первый выбор строки получает точное сообщение и файл с сервера через SDK и проверяет прежний checkpoint; после этого сохраняются проверенные байты. Следующее открытие сначала проверяет защищённую копию на Tecno и может создать плеер без сетевого запроса, sync или нового отправления. Основной экран показывает «С Tecno · без интернета»; серверная копия показывает результат сохранения. Ошибка сохранения не запрещает прослушать уже проверенный файл с сервера, но не обещает наличие офлайн-копии.

Хранение: отдельные файлы AES-256-GCM в Paths.document/matrix-voice-playback, случайный ключ на файл и до 10 небольших отдельных записей SecureStore. Аутентифицированные данные связывают копию с аккаунтом, HTTPS-сервером, device ID, комнатой, iPad, событием, отправителем, размером, длительностью и SHA-256 прежних байтов. Сохраняется результат прежней проверки шифрования, без токена, пароля, ключа Matrix-вложения или исходного пути плеера. Копия заново проверяет GCM-тег, формат, размер и digest. Повреждение или несовпадение дают cache miss и обычное проверенное чтение с сервера; произвольный файл не передаётся плееру. Это чтение ранее проверенной копии, а не свежая проверка события, доверия или доставки на iPad.

Запись, чтение и удаление ключей сериализованы. Новый файл проверяется до замены защищённой записи; ошибка записи ключа оставляет прежний файл и возможный шифрованный orphan до следующего успешного сохранения. Старые копии вне актуального списка удаляются при успешном сохранении новой. Выход и удаление сохранённого входа сначала удаляют ключи копий, затем их шифротекст. Черновик и сохранённый Matrix-вход используют прежние отдельные хранилища. Плеер получает временный расшифрованный файл в прежнем каталоге кэша; он удаляется при смене записи/закрытии экрана, а после принудительной остановки оставшиеся файлы с именем приложения очищаются перед восстановлением сессии. Очистка ограничена собственными каталогами и именами.

Сохранённая копия открывается до ожидания остановки автоприёма: для локального чтения не нужен новый SDK-синхронизатор. Если копии нет, сохраняется прежнее ожидание настоящей остановки перед сетевым чтением. Старая JS-сессия без voicePlaybackCacheVersion=1 просит полный Reload. Версия границы загрузки voiceUploadBoundaryVersion=3, формат входа и старые записи истории не менялись.

Проверки: TypeScript и lint без ошибок; все 407 тестов из 18 файлов прошли. Из них 20 новых тестов ядра копий, 7 адаптера файлов/ключей и 6 интеграционных проверок NativePeerTest с моделями SDK. Независимый Node AES-GCM проверяет запись/повторное открытие M4A и OGG, привязку к сессии, подмену файлов/метаданных, ошибки ключей, предел 10, отмену и удаление. Интеграция восстанавливает копию при недоступном fetch и SDK-загрузке, без sync или отправки. Нативный Expo AES, физическая сеть и звук этими моделями не доказаны.

Android-экспорт Hermes прошёл: `.expo/voice-offline-playback-export`, 1353 модуля, `entry-7a4ab062dca09983ab0a69eacf29074e.hbc`, 4 928 405 байт. Metro 192.168.100.8:8081: манифест, основной Android-код (6 675 188 байт), экран голоса (4 283 509) и адаптер копий (3 914 639) — HTTP 200; признаки нового API и хранения проверены. Новые зависимости, разрешения и EAS-сборка не добавлялись, подходит установленный APK versionCode 3. Expo Doctor не повторялся (прежний 21/21). Использованы документы Expo 57 [Crypto](https://docs.expo.dev/versions/v57.0.0/sdk/crypto/), [FileSystem](https://docs.expo.dev/versions/v57.0.0/sdk/filesystem/) и [SecureStore](https://docs.expo.dev/versions/v57.0.0/sdk/securestore/).

Проверка на Tecno:

1. При включённом интернете выполнить один полный Reload и открыть «Голос».
2. Открыть и прослушать одну строку «Ты», затем одну «iPad». У каждой после первого открытия должна появиться пометка о сохранении на Tecno.
3. Для проверки сохранения полностью остановить приложение через настройки Android и открыть снова при доступном Metro на Компьютере, без выхода и очистки данных.
4. Когда экран загрузился, выключить на Tecno Wi-Fi и мобильные данные. Приложение оставить открытым. По очереди заново открыть эти две строки и прослушать обе: пометка должна быть «С Tecno · без интернета». Переключение между строками проверяет новое открытие копии, а не продолжение прежнего плеера.
5. Вернуть связь после проверки. Полный запуск development client без доступа к Metro — отдельный сценарий; для текущего теста код загружается до отключения сети.

Офлайн-прослушивание и сохранение копий после остановки пока требуют подтверждения владельцем. Полный чат, дневник, восстановление после удаления данных и исходящее ГС в ленте Element X остаются последующими этапами.

## Предыдущий этап: история своих отправленных записей

05.10.2026 владелец попросил продолжить работу и отложил отдельную проверку кнопки отмены. Она не является текущим блокером этапа. Подтверждённый результат предыдущего теста сохраняется: после возврата интернета и автоматического Reload повторная ручная отправка дошла на iPad и проигралась. Причина Reload отдельно не установлена.

Добавлена общая история: последние 5 подтверждённых отправленных записей Tecno и 5 полученных с iPad. Блок записи расположен над историей; записи помечены «Ты» и «iPad», свои дополнительно выделены цветом. Плеер открывается внутри выбранной строки, её открытие сохраняет положение прокрутки. Список сортируется по времени локального подтверждения/сохранения, это не время прочтения собеседником. Свою историю пополняют новые отправки после загрузки этого обновления. Исторические сообщения до него автоматически не сканируются.

Своё голосовое запоминается только после серверного события, проверки шифрования сообщения/вложения и сравнения расшифрованных байтов с исходной записью. В защищённой сессии сохраняется компактный список идентификаторов и контрольных сумм, привязанный к комнате, своему аккаунту и устройству. Пароль, расшифрованные файлы, путь проигрывания и ключ вложения в историю не записываются. Ошибка сохранения истории сообщает, что запись уже отправлена; повтор этой же записи остаётся закрыт. Синтетический звук из «Диагностики» в свою историю не попадает.

После восстановления сессии открытие записи заново получает точное событие и файл с сервера и расшифровывает существующими ключами. Проверяются отправитель, устройство, комната, шифрование, контрольная сумма и длительность. Это чтение не запускает новую отправку и не сдвигает отметку приёма голосовых с iPad. Смена комнаты/собеседника удаляет старую историю из локальной сводки; выход удаляет защищённую сессию. Формат входа version 1 сохранён, старые записи без ownAudioHistory открываются как прежде. Старая сессия Fast Refresh отклоняется перед отправкой по версии callback 3 и просит полный Reload.

Пройдены TypeScript, lint, все 374 теста из 16 файлов и Android-экспорт Hermes (1351 модуль, `.expo/voice-own-history-export`, `entry-49993299bedcb4623af228466d1d0572.hbc`, 4 888 726 байта). Новые тесты используют модель SDK и независимое шифрование Node: это проверка адаптера и хранения, а не самостоятельное доказательство работы на телефоне. Metro по LAN выдаёт манифест и обновлённые основной код, экран голоса и нативную сессию HTTP 200. Зависимости/нативные разрешения не менялись, подходит установленный APK versionCode 3; новый EAS-build не нужен. Expo Doctor не повторялся, прежний результат 21/21.

Проверка владельцем:

1. Один раз выполнить полный Reload, открыть «Голос» при включённом интернете.
2. Записать новую короткую фразу, отправить на iPad и проверить появление строки «Ты» в истории. На iPad открыть и прослушать новый файл.
3. На Tecno открыть эту строку и прослушать запись с сервера.
4. Полностью остановить приложение Tecno через настройки Android, затем открыть снова без выхода и очистки данных. Metro на Компьютере оставить работающим. Открыть ту же запись «Ты» и прослушать её снова.
5. Отправить ответ с iPad и проверить, что в общей истории появляется отдельная строка «iPad», а своя запись сохраняется.

Результат проверки владельцем 05.10.2026: «всё успешно включается и помечается как надо». Подтверждены открытие/воспроизведение записей и правильные пометки общей истории. Это сообщение владельца после инструкции проверки, без самостоятельного доступа агента к устройствам; полная остановка Tecno и повторное прослушивание после неё отдельно в ответе не описаны. Превращение M4A в обычное голосовое прямо в ленте Element X, полный чат, дневник и восстановление после удаления данных остаются отдельными этапами.

## Предыдущий этап: отмена зависшей подготовки и раздел «Голос»

Результат повторной проверки, 05.10.2026: после включения интернета приложение само выполнило Reload. Владелец ещё раз нажал отправку; запись дошла на iPad и проигралась. Подтверждена ручная отправка сохранившегося черновика после возвращения сети и автоматического Reload. Работа без любого Reload и разблокировка после отдельной отмены пока не подтверждены. Автоматическая отправка черновика не реализована: после ошибки связи отправку запускает владелец.

Проверен журнал Metro: есть повторные запросы основного кода и модулей, ошибки в доступном журнале не записаны. Эти запросы не сообщают причину Reload и могут включать проверки самого агента. В установленном React Native 0.86.3 найден механизм `HMRClient.registerBundleEntryPoints`: при недоступном HMR он вызывает `DevSettings.reload('Bundle Splitting – Metro disconnected')` (node_modules/react-native/Libraries/Utilities/HMRClient.js:323–326). Это возможная причина перезапуска development client при потере связи с компьютером, а не доказанный источник конкретного Reload на Tecno. Код приложения и настройки сборки в этом дополнении не менялись.

05.10.2026 владелец сообщил: отправить удалось после ручного Reload. Без него отправка зависала, предположительно на «Подготавливаем действие»; отмена завершала ожидание на экране, но остальные кнопки оставались заблокированы. Следовательно, работа после возврата Wi-Fi без Reload пока не подтверждена.

В исходниках найдены неограниченные ожидания GET и чтения JSON при автоприёме. Теперь `matrix-read.ts` ограничивает оба этапа общими 15 секундами и завершает ожидание сразу после отмены, даже если транспорт игнорирует AbortSignal. Поздний ответ не может продолжить обработку или вызвать SDK. В тестах реального адаптера NativePeerTest с моделью SDK воспроизведены зависший запрос и зависшее тело: пауза завершает остановку, затем новая операция использует тот же клиент; поздний ответ не вызывает загрузку аудио. Результат повторной проверки на Tecno/iPad приведён выше; отдельная отмена ещё не подтверждена владельцем.

Подготовка голосовой отправки ограничена одной минутой; после входа в этап передачи SDK действует прежнее ожидание до пяти минут. Во время настоящей нативной остановки повторные сетевые операции остаются закрыты до её завершения, чтобы не запускать два синхронизатора. Запись, прослушивание черновика и вкладки доступны после отмены. При неподтверждённой остановке SDK остаётся явное сообщение о необходимости остановить приложение. Старая сессия Fast Refresh с версией callback до 2 отклоняется до ожидания автоприёма и просит один полный Reload.

Основная вкладка переименована в «Голос»: история входящих, запись, прослушивание и отправка. Ручной приём, повтор автоприёма, удаление черновика, статусы доверия, информация об устройствах и прежние проверки находятся в «Диагностике». Переключение вкладок сохраняет владельца защищённого черновика; воспроизведение останавливается, микрофон сам не включается.

Пройдены TypeScript, lint, 268 связанных тестов и Android-экспорт Hermes (1350 модулей, `.expo/voice-cancel-fix-export`). Зависимости, формат защищённого черновика и нативная конфигурация не изменялись; подходит установленный APK versionCode 3.

Повторная проверка на устройстве:

1. Один раз выполнить полный Reload для загрузки нового кода; проверить появление вкладок «Голос» и «Диагностика».
2. При включённом интернете записать новую короткую фразу и дождаться «Черновик сохранён на Tecno».
3. Отключить Wi-Fi и мобильный интернет, нажать отправку. После ошибки связи черновик должен остаться доступным.
4. Включить интернет, без Reload снова нажать отправку и проверить получение файла на iPad. Отправка черновика остаётся ручной.
5. Отдельно проверить отмену: в «Диагностике» начать ручной приём, дождаться ожидания нового голосового и нажать верхнюю отмену. Вернуться в «Голос»: запись и прослушивание доступны сразу после завершения действия на экране; сетевые кнопки открываются после остановки SDK. Повторный ручной приём или отправка не должны требовать Reload.

## Предыдущее исправление: маркер отправки при возвращении Wi-Fi

Владелец сообщил: после возвращения Wi-Fi приложение само делает Reload, показывает «отправка начиналась», но файл не приходит на iPad. На уточнение ответил, что до включения Wi-Fi уже появилось «Запись не отправлена. Черновик сохранён на Tecno». Значит, первый тест возвращения сети не пройден. Происхождение автоматического Reload на телефоне не установлено; агент устройством не управлял и нативных логов телефона не получал.

В коде найдена отдельная причина преждевременной блокировки: отметка `sending` сохранялась сразу после первого GET, ещё до остановки автоприёма, подготовки SDK, комнаты, ключей и слушателя. Эта ошибка исправлена. Первый GET теперь не меняет защищённую запись. Подготовка SDK также оставляет её `draft`. После подготовки callback перед самым `timeline.sendAudio(params, info)` ещё раз проверяет связь, отмену и принадлежность открытого экрана; только затем сохраняет отметку. Закрытый экран не может продолжить поздний вызов. Старая сессия из Fast Refresh без новой версии callback отклоняется до отправки и просит полный Reload. Ошибка до этого этапа отдельно сообщает, что подготовка остановлена и черновик сохранён.

Повторная проверка на Tecno и iPad ещё нужна:

1. При включённом Wi-Fi выполни полный **Reload** и дождись автовхода. Компьютер с Metro оставь включённым. Если прежняя запись уже помечена «Отправка этой записи уже начиналась», для нового теста нажми **«Записать новую фразу»**: это явно заменит прежний тестовый черновик. Запиши фразу на 3–5 секунд, останови и дождись сохранения.
2. Выключи **Wi-Fi и мобильный интернет** на Tecno. Нажми отправку и дождись именно **«Запись не отправлена. Черновик сохранён на Tecno»**.
3. Включи Wi-Fi. Если приложение само перезагрузится, дождись автовхода. Отправку пока не нажимай: та же запись должна оставаться доступной для прослушивания и ручной отправки, без предупреждения «отправка начиналась». Новый файл на iPad пока не должен появиться.
4. Прослушай сохранённую фразу и один раз нажми **«Отправить голос на iPad»**. Дождись подтверждения отправки/расшифровки, затем прослушай один новый аудиофайл на iPad.

Прежние записи с уже сохранённым `sending` автоматически не разблокируются: их формат не позволяет доказать, был ли вызван SDK или файл остался в его очереди. Отсутствие вложения на iPad сейчас не доказывает отсутствия отложенной отправки. Само обновление не удаляет и не повторяет эти записи. Если новая версия реально начала передачу SDK и результат неизвестен, повтор по-прежнему блокируется. Остаётся небольшой неопределённый промежуток между сохранением отметки и вызовом SDK; защита от дублей в этом случае консервативна. ## Подготовка проверки потери связи перед отправкой (4 октября)

После основной инструкции проверить сохранение, открытие и отправку черновика после полной остановки Tecno владелец ответил «Все работает, идем дальше». Этот сценарий отмечен как подтверждённый пользователем. Агент устройствами не управлял; удаление черновика отдельной кнопкой, выход и дополнительные повторные остановки этим ответом отдельно не подтверждены.

Перед отправкой приложение проверяет доступность своего Matrix-сервера. Если интернет выключен, ответ сервера неверный или сервер не отвечает за 8 секунд, отправка не начинается. Та же запись остаётся зашифрованным черновиком на Tecno, доступным для прослушивания и новой ручной попытки. Появляется статус **«Запись не отправлена. Черновик сохранён на Tecno»** с пояснением. Во время проверки доступна кнопка **«Отменить проверку связи»**; закрытие экрана или уход приложения в фон также останавливают эту проверку. Возвращение интернета само не отправляет запись.

Проверка на устройствах ещё предстоит:

1. При включённом интернете выполни полный **Reload** на Tecno, дождись автовхода и открой «Запись голоса» на экране «Устройства». Компьютер с Metro оставь включённым. Запиши фразу на 3–5 секунд, например «Проверка без интернета», останови запись и дождись **«Черновик сохранён на Tecno»**.
2. На Tecno выключи **Wi-Fi и мобильный интернет**. Приложение оставь открытым; Reload и полную остановку сейчас не делай. Прослушай черновик и нажми **«Отправить голос на iPad»**. В течение примерно 8 секунд должен появиться статус о том, что запись не отправлена и черновик сохранён. На iPad нового файла быть не должно.
3. Включи Wi-Fi обратно, вернись к открытому экрану и снова нажми **«Отправить голос на iPad»** один раз. Должна отправиться та же фраза, без новой записи. Дождись подтверждения отправки и расшифровки, затем открой новый аудиофайл в Element X на iPad. Он должен появиться один раз.
4. Дополнительно можно проверить кнопку **«Отменить проверку связи»** во время ожидания без интернета. После отмены черновик должен остаться доступным для прослушивания и ручной отправки. Не выходи из аккаунта: выход удаляет локальный черновик.

Технические границы: используется публичный read-only [GET /_matrix/client/versions](https://spec.matrix.org/v1.18/client-server-api/#get_matrixclientversions) без токена, cookies, идентификаторов аккаунта и аудиобайтов. В ответе проверяются HTTP 200, схема `versions` и максимальный принятый размер 16 KiB. Это проверка связи с сервером, а не проверка доверия, доступности загрузки медиа или доставки на iPad. Заголовки `Cache-Control: no-cache, no-store` и `Pragma: no-cache` требуют свежей проверки: установленный native fetch Expo 57 передаёт заголовки, но не передаёт `RequestInit.cache` в нативный запрос. Дополнительно `cache: 'no-store'` задан для стандартного fetch. Сверены [Expo SDK 57 Fetch/TextEncoder](https://docs.expo.dev/versions/v57.0.0/sdk/expo/), [AppState React Native 0.86](https://reactnative.dev/docs/0.86/appstate) и исходники установленного Expo.

Тайм-аут и отмена ограничивают весь GET, включая чтение тела. Поздний ответ отменённой проверки не может вызвать передачу аудио SDK. После исправления 5 октября первый GET не сохраняет отметку отправки: перед ней ещё выполняются подготовка SDK и свежая проверка связи непосредственно перед нативной отправкой. Если связь потеряна уже после отметки, повтор остаётся отключённым: сначала нужно проверить iPad, запись могла уже попасть на сервер. Автоматического повтора или очереди отправок нет. Полный запуск/автовход без интернета и загрузка несохранённого экрана из Metro без Wi-Fi не реализованы этим этапом.

Три новые проверки адаптера подтверждают неизменность ключа и шифротекста при офлайне/отмене и сохранение блокировки неопределённой отправки после открытия. ## Подтверждённый этап: зашифрованный голосовой черновик на Tecno

После инструкции проверить автоматический приём владелец ответил «всё успешно идем дальше». Автоматическое получение новых голосовых с iPad на Tecno отмечено как подтверждённое пользователем. Агент самостоятельно устройствами не управлял; отдельные результаты каждого шага расширенной инструкции не сообщались.

Теперь завершённая запись до 15 секунд сохраняется на Tecno как один зашифрованный черновик. До нажатия «Отправить голос на iPad» она не передаётся на Matrix-сервер. После закрытия приложения черновик восстанавливается для прослушивания и ручной отправки. Новая запись явно заменяет прежний черновик; «Удалить черновик» и выход из аккаунта удаляют его. Это локальная проверка сохранения, не реализация полного дневника или облачного восстановления.

Основной сценарий сохранения/открытия/ручной отправки подтверждён ответом владельца «Все работает, идем дальше». Ниже сохранена инструкция для повторной проверки; дополнительные проверки удаления из шага 5 отдельно не подтверждены:

1. На Tecno выполни полный **Reload**, дождись автовхода и открой карточку «Запись голоса». Компьютер с Metro оставь включённым; при повторном открытии development APK нужен доступ к нему по Wi-Fi.
2. Запиши тестовую фразу на 3–5 секунд, например «Черновик после закрытия». Останови запись и дождись **«Черновик сохранён на Tecno»**. Прослушай её, но пока не отправляй. На iPad новое вложение не должно появиться.
3. Полностью останови приложение Tecno через настройки Android → приложения → наше тестовое приложение → «Остановить». Данные не очищай, из аккаунта не выходи. Снова открой приложение и дождись автовхода.
4. В карточке должна восстановиться та же запись со статусом сохранённого черновика. Прослушай её, затем один раз нажми **«Отправить голос на iPad»**. Дождись подтверждения отправки и расшифровки. На iPad открой новый аудиофайл в Element X и проверь ту же фразу.
5. После успешной отправки ещё раз останови и открой Tecno: отправленный черновик не должен восстановиться и повторно отправиться. Для дополнительной проверки запиши другой черновик, нажми «Удалить черновик» и проверь отсутствие записи после открытия.

Постоянная копия — AES-256-GCM с новым случайным ключом и nonce 12 байт, tag 16 байт. Ключ и компактная запись состояния хранятся отдельно в SecureStore с `WHEN_UNLOCKED_THIS_DEVICE_ONLY`; шифротекст — в каталоге документов приложения. Аккаунт, сервер, device ID, комната, адресат, длительность, размер и waveform привязаны к записи и входят в authenticated additional data. Чужой контекст отклоняется до расшифровки. На диск сначала записывается шифротекст, затем он перечитывается и расшифровывается нативным Expo Crypto; каждый байт сравнивается с оригиналом до подтверждения сохранения ключа.

После успешного сохранения исходный временный файл микрофона удаляется, предпрослушивание получает отдельную проверенную копию в кэше с генерируемым именем. На обычном закрытии копия удаляется; при следующем открытии удаляются оставшиеся копии из собственного каталога кэша, затем создаётся новая. Во время записи, сохранения и проигрывания существуют временные открытые байты/файлы. Полная остановка процесса может оставить временный кэш; это не обещание немедленного удаления после выключения телефона. Файлы другой сессии или произвольные пути не удаляются. Ключ удаляется до очистки шифротекста; ошибка SecureStore сохраняет прежнюю запись. Очистка файлов после удаления ключа выполняется по возможности.

Перед Matrix-вызовом сохраняется отметка начала отправки. При прерывании, отмене или неопределённом результате после открытия показывается «Отправка этой записи уже начиналась»; повторная отправка отключена, запись остаётся доступной для прослушивания/удаления. Нужно проверить iPad. Автоматической отправки или повтора нет. Только подтверждённый результат прежней Matrix-проверки удаляет защищённый черновик. Файловые изменения, ключ, восстановление и выход используют одну очередь; закрытие экрана ждёт начатое сохранение перед удалением источника.

Проверено: TypeScript, lint и **232 связанных теста** — 35 черновик/реальный адаптер Expo с независимым Node AES-GCM/ошибки диска и SecureStore/привязка/прерывание/передача из записи, 15 запись/отмена/восстановление, 82 входящее аудио, 7 автоприём, 16 сессия/история, 32 обмен с iPad, 5 прежний текст, 32 отправка аудио, 5 ожидание остановки, 3 настоящий Metro resolver Android/iOS/web. Нативные Expo-порты в тестах моделируются; AES и сохранение после остановки на Tecno ими не доказаны. Android-экспорт Hermes: `.expo/voice-draft-export`, 1348 модулей, `entry-67ee9eb96d680670ea52d1fd915375e5.hbc`. Metro: LAN-манифест и основной Android bundle HTTP 200 (6 559 459 байт); отдельно загружаемый экран голоса HTTP 200 (4 265 848 байт), содержит новый контроллер, AES-вызовы и передачу предпрослушивания.

Новые зависимости и нативные настройки не добавлялись. `expo-crypto ~57.0.3`, `expo-file-system ~57.0.7` и `expo-secure-store ~57.0.4` уже установлены в проекте/APK versionCode 3; config Expo Crypto включает нативный AES-модуль Android. ## Подтверждённый этап: автоматический приём голосовых с iPad

После появления истории владелец сообщил: «вроде работает, но чтобы получить новую запись пришлось нажать кнопку получить пропущенное». Это частичное подтверждение истории и подтверждение неудобства ручного приёма; сохранение нескольких записей после остановки отдельно не подтверждено.

Теперь на открытом экране «Устройства» приём запускается после автовхода. Пропущенные записи ищутся автоматически, затем новые голосовые добавляются в историю без кнопки получения. Вверху отображается этап автоприёма. Ручные проверки свернуты в «Ручная проверка приёма». Новая запись не заменяет плеер и не прерывает выбранный звук; для прослушивания используется «Открыть запись».

1. Выполни полный **Reload** на Tecno, дождись автовхода и статуса **«Автоприём включён»**. Оставь экран «Устройства» открытым.
2. Отправь с iPad в нашу комнату Element X две разные короткие фразы. Кнопки получения на Tecno не нажимай. Обе записи должны появиться в истории сами, самая новая — первой. Проверка новых событий идёт примерно раз в 5 секунд; скачивание и получение ключей могут занять дополнительное время.
3. Открой и прослушай каждую запись. Пока одна проигрывается, отправь ещё одну с iPad: она должна добавиться в список, не прерывая звук.
4. Сверни приложение на Tecno, отправь новую фразу с iPad, затем вернись на экран «Устройства». Она должна подхватиться автоматически без ручной кнопки и без повторного получения уже сохранённых записей.
5. Полностью останови приложение без очистки данных, отправь фразу с iPad и открой Tecno снова. После автовхода проверь автоматическое получение, сохранённый список и открытие более ранней записи.

Используется один сохранённый Matrix-клиент и один непрерывный native sync на время автоприёма. Перед чтением истории, отправкой, проверкой доверия и выходом приём отменяется; новое действие ждёт фактической остановки SDK. Запись микрофона, фон, переход на другой экран и вкладка «Диагностика» ставят приём на паузу. После возвращения и завершения действия приём возобновляется. При сетевом сбое повтор выполняется через 15/30/60 секунд; ошибка остановки SDK блокирует повтор до перезапуска приложения. Replay эффектов/Fast Refresh также ждёт прежней очистки.

Перед поиском пропущенных устанавливается серверная граница будущего приёма, чтобы не потерять событие на переходе к новым записям. Пропущенные события обрабатываются от старых к новым; курсор страницы сдвигается после полной обработки и сохранения. Каждый аудиофайл проходит прежние проверки Megolm, Matrix v2, размера, SHA-256 и нативной расшифровки; участники и доверие дополнительно перечитываются перед каждым новым файлом. Автоприём удаляет свою временную копию после проверки и передаёт экрану только сохранённые метаданные. Плеер истории получает отдельную копию по выбору пользователя.

Это модели SDK; реальный автоматический приём позже подтверждён сообщением владельца «всё успешно идем дальше». ## История последних пяти голосовых с iPad: предыдущая ручная проверка

В существующую сессию SecureStore добавлено необязательное поле истории; старые сохранения версии 1 продолжают открываться. При первой новой записи прежняя единственная отметка сохраняется в истории. На диске общий контекст комнаты/отправителя/device ID хранится один раз, а каждая запись — компактным набором ID события, SHA-256 расшифрованных байтов, размера, длительности и времени получения. Список ограничен пятью событиями; повтор того же ID не создаёт дубликат, изменение контрольной суммы того же ID отклоняется. Ключи вложений, дескрипторы, локальные пути и аудиобайты в историю не записываются. Ошибка нативного сохранения обрабатывается; предыдущий вход и ключи не удаляются, запись не появляется в подтверждённом списке до успешного сохранения.

Чтение истории не отправляет сообщений, не запускает sync, не обновляет последнюю отметку получения и не создаёт дубликаты. Новая комната/аккаунт iPad очищают старую историю; обновление токенов её сохраняет. В плеере одновременно открыта одна входящая запись.

## Исправление для Element X

В проверенных исходниках Element X iOS на коммите `9f141585a2eb641c38e18c21d7030e4b95a53a19` наличие `voice` выбирает специальный загрузчик, который отклоняет MIME, не начинающийся с `audio/ogg`, ещё до загрузки файла. Наша запись содержит AAC/M4A с MIME `audio/mp4`. Это конкретная несовместимость отправки, соответствующая наблюдаемому поведению; версия Element X на iPad и журнал самого iPad не получены.

Теперь M4A отправляется через `Timeline.sendAudio` как обычное зашифрованное аудиовложение без `voice`. Element X показывает такой файл через общий просмотр вложений. Реальный MIME и байты записи сохранены; переименование M4A в OGG не используется. Специальный голосовой плеер Element X с волной пока не поддерживается этим сценарием: установленный Expo Audio 57.0.5 не предоставляет Android-запись OGG/Opus в своём публичном API и нативных перечислениях.

Исправление доставлено через Metro; воспроизведение нового аудиовложения на iPad подтверждено владельцем. Для повторения сценария после старого кода нужны **Reload на Tecno и новая запись**. APK versionCode 3 уже содержит необходимые модули; дополнительная EAS-сборка для этой правки не требуется. Старое сообщение на iPad не изменяется автоматически.

## Проверка на устройствах

1. Если APK с микрофоном уже установлен, выполни Reload на Tecno. Оставь компьютер и Tecno в одной сети. Открой сервер разработки `http://192.168.100.5:8081`, дождись автоматического входа. Установка APK по ссылке ниже нужна только для более старой сборки без микрофона.
2. Во вкладке **«Устройства»** найди карточку **«Запись голоса»**. Под заголовком должна быть подсказка, что на iPad запись придёт как аудиофайл. Сохранённая комната и аккаунт iPad используются без повторного сравнения эмодзи.
3. Нажми **«Записать голос»**, разреши микрофон и произнеси тестовую фразу, например «Проверка голосового сообщения». Нажми **«Остановить запись»**. Ограничение — 15 секунд; слишком короткая запись (меньше 0,8 секунды) не принимается.
4. Нажми **«Прослушать перед отправкой»**. Должен быть слышен голос. Можно удалить запись или записать новую. Пока отдельная кнопка отправки не нажата, файл остаётся только на Tecno.
5. Нажми **«Отправить голос на iPad»** и оставь приложение открытым. Этапы отображаются сверху. Дождись **«Голос отправлен и расшифрован»**.
6. Нажми **«Слушать запись с сервера»** на Tecno. Здесь проигрывается отдельная копия, полученная после скачивания и нативной расшифровки, а не исходный файл микрофона.
7. На iPad в Element X открой нашу комнату «Matrix · проверка двух аккаунтов». Нажми **новое аудиовложение** `matrix-voice-….m4a`, затем включи воспроизведение в открывшемся просмотре. Должна звучать та же фраза. Прежнее сообщение со специальной кнопкой голосового остаётся в старом формате.

Сообщи отдельно: слышна ли запись перед отправкой, успешен ли результат на Tecno, слышна ли копия с сервера на Tecno и голосовое на iPad. При ошибке достаточно текста ошибки и последнего этапа. Пароли и ключи передавать не нужно.

Запись и воспроизведение работают на открытом экране. При уходе из приложения незавершённая запись отменяется. Отмена ожидания отправки не отзывает уже принятый очередью SDK файл: он может прийти позже. Перед повтором проверь комнату на iPad. Приложение само не запускает повторную отправку.

## Что реализовано

- `expo-audio ~57.0.5` и требуемая прямая зависимость `expo-asset ~57.0.18` установлены через `npx expo install`. Версии Expo ~57.0.26, React 19.2.3, React Native 0.86.3 и Matrix SDK 0.10.2 сохранены.
- Expo Audio создаёт AAC в контейнере M4A, один канал, 64 кбит/с. Микрофон запрашивается при нажатии записи. Ограничение времени задано и нативному рекордеру, и контроллеру экрана. До чтения байтов в JavaScript проверяются собственный каталог cache, длительность и размер не более 1 МиБ.
- Используются документированные `useAudioRecorder`, `useAudioPlayer` и `useAudioPlayerStatus`. Отмена сериализована с выдачей разрешения, подготовкой и остановкой: запоздалое разрешение не запускает микрофон после отмены. Плееры освобождаются хуками, временные собственные записи удаляются при замене и уходе с экрана по мере возможности.
- Плагин Expo Audio включает микрофон; фоновая запись и воспроизведение выключены. Проверка сгенерированной конфигурации показала Android `RECORD_AUDIO` и `MODIFY_AUDIO_SETTINGS`, без фонового сервиса записи. Каталоги android/ios вручную не создавались.
- Используется фактический `Timeline.sendAudio(params, audioInfo)` SDK 0.10.2, с `UploadSource.Data`, MIME `audio/mp4` и длительностью в миллисекундах. Метаданные waveform из рекордера не прикрепляются к M4A как специальное голосовое. Полный формат API проверен по установленным сгенерированным типам и Rust SDK SHA `1c44fb6`.
- Сохранены проверки участников комнаты, её шифрования и доверия к Tecno и аккаунту iPad. Успех требует удалённого события из sync и совпадения размера, MIME и длительности. Наличие несовместимого признака `voice` у M4A даёт ошибку. Завершение помещения в очередь само по себе успехом не считается.
- По event ID проверяется исходное зашифрованное событие на сервере. Затем `getMediaFile` с `useCache=false` дважды получает файл: сначала шифротекст для проверки SHA-256, затем нативно расшифрованное содержимое. Все расшифрованные байты должны совпасть с записью. Передаётся безопасное имя файла и доступный каталог cache — обход прежней проблемы с системным временным каталогом сохранён.
- Для прослушивания серверного результата создаётся отдельный файл из проверенных расшифрованных байтов. Он удаляется при новой записи или уходе с экрана; это временный тест, не история голосовых сообщений. Исходный MediaSource JSON с ключом вложения и сырые ошибки SDK не выводятся.
- Старый APK открывает сохранённую сессию и показывает просьбу обновиться, не загружая отсутствующий нативный Expo Audio. Прежний тест синтетического WAV перенесён во вкладку «Диагностика».
