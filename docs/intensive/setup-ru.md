# Интенсив: как включить сервер переписки

Это делает Арт сам. Займёт около 15 минут. Ключи и пароли никому не пересылай,
кроме двух публичных строк в шаге 4.

## 1. Проект Supabase

1. Зайди на https://supabase.com и создай аккаунт (можно через GitHub).
2. New project. Название: `code-of-stalker-intensive`. Регион: Frankfurt
   (`eu-central-1`) или другой европейский. План: Free.
3. Пароль базы данных сохрани в своём менеджере паролей. Он нужен только тебе.

## 2. Вход без почты

Authentication → Sign In / Providers → Email:

- **Allow new users to sign up**: включено.
- **Confirm email**: выключено. Почта у нас ненастоящая, её выводят из 12 слов,
  письма никуда не уходят.
- Нажми Save.

Authentication → Multi-Factor: **TOTP** (Authenticator app) включено.
Обычно включено по умолчанию.

## 3. Таблицы и правила доступа

1. SQL Editor → New query.
2. Открой в репозитории файл `supabase/intensive-schema.sql`, скопируй его
   целиком и вставь.
3. Run. Должно закончиться без ошибок («Success. No rows returned»).

Все права проверяет сервер, а не приложение: даже зная код сайта, чужой
человек не прочтёт чужую переписку и не назначит себя проводником.

## 4. Что прислать мне

Project Settings → API Keys (или Data API):

- **Project URL**, вида `https://abcdefgh.supabase.co`;
- **Publishable key**, начинается с `sb_publishable_…`.

Эти две строки публичные: их видит любой браузер, который открывает сайт.

**Не присылай** secret key (`sb_secret_…`), `service_role`, пароль базы.
Если прислал случайно: Project Settings → API Keys → перевыпусти его.

Я впишу URL и ключ в `src/features/intensive/config.ts`. После этого сайт сам
пустит запросы к этому серверу (правило безопасности строится из того же файла),
а GitHub раз в день будет «будить» бесплатный проект, чтобы он не засыпал.

## 5. Защити GitHub

Код сайта открыт, а публикует его каждый пуш в `main`. Включи двухфакторный
вход в GitHub: Settings → Password and authentication → Two-factor
authentication. Так никто не подменит сайт и не украдёт переписку через него.

## 6. Яна: главный админ

1. Яна открывает сайт → Уровни → Интенсив → «Создать аккаунт», записывает
   12 слов на бумагу, задаёт имя и PIN.
2. На экране ожидания у неё появится код вида `FE6B-DC41`. Пусть пришлёт его тебе.
3. В Supabase: SQL Editor → New query:

   ```sql
   select id, name, created_at from public.profiles order by created_at desc limit 5;
   ```

   Найди строку с её именем, где `id` начинается с этих 8 знаков (без дефиса,
   в нижнем регистре: `fe6bdc41…`).
4. Затем (подставь эти 8 знаков в нижнем регистре):

   ```sql
   insert into public.main_admins (user_id)
   select id from public.profiles where id::text like 'fe6bdc41%';
   ```

   Должно быть «1 row affected». Если 0, проверь код.

5. Яна нажимает «Проверить снова» (или заново открывает Интенсив). Приложение
   попросит её подключить приложение с кодами (Google Authenticator, Aegis,
   2FAS и т. п.). После этого у неё вкладки «Переписки» и «Люди».

Главного админа назначают только здесь, в SQL. Из приложения это сделать нельзя.

## 7. Проверка

1. Яна во вкладке «Люди» → «Команда» выбирает себя и включает «Проводник».
2. Второй человек (лучше идущий из России) создаёт аккаунт и присылает Яне код.
3. Яна находит его в «Ждут» и назначает проводника.
4. Оба пишут друг другу. Сообщения приходят без перезагрузки.
5. Идущий закрывает вкладку и входит снова по PIN.

Если что-то не так, пришли мне скриншот и время, когда это было.

## Что важно знать

- **12 слов** — единственный способ вернуть аккаунт. Их не знает ни Яна,
  ни разработчик. Потерял слова и PIN: аккаунт не вернуть, нужен новый,
  и Яна заново назначает проводника. Старую переписку новый аккаунт не увидит.
- **5 неверных PIN** стирают аккаунт с этого устройства. Вернуть можно
  12 словами.
- **Шифрование**: сервер хранит только шифр. Читать могут участники переписки:
  идущий, его проводник, админ этого проводника и главные админы.
- **Смена проводника**: история остаётся у идущего, новый проводник видит
  всю переписку, прежний теряет к ней доступ.
- **Бесплатный план**: 500 МБ базы, этого хватит на годы текстовой переписки.
  Если GitHub-«будильник» перестанет работать (GitHub выключает расписания
  в репозиториях без активности 60 дней), проект уснёт через неделю. Разбудить:
  Supabase → проект → Restore.
