# Кеш графики веб-версии

Сборка: `npm run export:web`. Подготовка существующего сайта: `npm run prepare:site`.
Второй шаг пересчитывает кеш после разбиения WASM на части для ограничения размера файлов Sites.
Не публикуйте сырой `expo export` без подготовки кеша.

На HTTPS (и localhost) после загрузки страницы регистрируется service worker.
В фоне он сохраняет иллюстрации, шрифты, JS-анимации, WASM и оболочку приложения в Cache Storage.
Каждый файл проверяется по размеру и SHA-256. Версия зависит от всех ресурсов и кода worker.
Статическая HTML-оболочка встроена в worker из сборки: добавляемые хостингом скрипты не изменяют её контрольную сумму.
Служебные иконки Expo имеют побайтно одинаковые копии в `graphics-cache-assets`: worker сохраняет исходные адреса для приложения, обходя ограничение хостинга на пути `node_modules`.
При повторном открытии эти ресурсы читаются локально, в том числе без сети после полной первой загрузки.

Обновление сначала полностью загружается в отдельный кеш. Частичная загрузка удаляет только новый незавершённый кеш.
Проверка маленького `graphics-cache-version.json` идёт без HTTP-кеша: при запуске,
возвращении в приложение, восстановлении сети и раз в минуту на видимой странице.
Если версия изменилась, worker запрашивается с `?release=<версия>` и `updateViaCache: 'none'`.
Область `/` и регистрация остаются прежними; адрес запроса явно обходит старый HTTP-кеш встроенного браузера.
Полностью загруженный worker активируется сразу. Старые открытые страницы остаются
привязаны к своему набору JS, WASM и иллюстраций, включая перезапуск worker браузером.
Страница автоматически перезагружается после двух секунд без взаимодействий,
когда нет записи, несохранённого текста, открытого окна, оптимизации или операций сохранения.
Обновление сохраняет текущий URL и локальные данные; закрывать вкладки не требуется.
Неизменившиеся файлы повторно используются после проверки SHA-256.
Worker удаляет только ненужные кеши с префиксом `watcher-graphics-v1-`: сохраняет
текущий, используемые открытыми страницами и один предыдущий снимок.
Служебные привязки страниц хранятся отдельно в `watcher-graphics-clients-v1`.

Однократная миграция со старого worker: открыть `/update` на том же адресе.
Этот маршрут отсутствовал в старом кеше и получает новую оболочку через сеть,
после чего дальнейшие обновления применяются автоматически. Закрывать Telegram не нужно.

IndexedDB `watcher-product-local-v1`, аудио, ключ шифрования, резервные копии и настройки не изменяются.
Worker перехватывает только GET-запросы статических путей и переходы по маршрутам приложения.
Аудио, blob-URL, запросы с Range, API и сторонние адреса проходят как обычно.
Разрешение постоянного хранения из существующего защищённого режима распространяется и на Cache Storage этого адреса.
Браузер может отказать в кеше или удалить данные; без service worker приложение продолжает работать через сеть.
Перед загрузкой проверяется доступное место; дополнительно остаётся 32 МиБ для голосовых записей.

Проверки: `npm run test:web-cache`, `npx expo lint`, `npx tsc --noEmit`.
`graphics-cache-manifest.json` содержит версию, список файлов, размеры и контрольные суммы для диагностики.
