Watcher — графический движок продукта на Rust
Состояние: 2026-10-09

Назначение
Это движок настоящей web-версии приложения. Отдельный эксперимент
experiments/laboratory-rust-glass сохранён и не используется как страница продукта.
По умолчанию Art.web выбирает Rust/WASM/wgpu: WebGPU, затем WebGL2.

Граница ответственности
Rust рассчитывает время, easing, промежуточные transforms/opacity, морфинг,
проявления, dissolve, частицы, touch-инерцию, декодер и реакцию графики на звук.
React передаёт размеры, события, целевые состояния и измеренные аудиоданные.
Разметка, текст, доступность, навигация, запись, разрешения, хранилище и Matrix
остаются в своих существующих модулях. Rust ElementTimeline обновляет стили
текстовых и интерфейсных слоёв; React не вычисляет их промежуточные кадры.

Состав
16 видов сцен: glass, rain, distance, cells, diary, basic, guidance, parallel,
intensive, comparison, attention, crowd, voice, insight, gallery, mirror.
Дополнительно: появление текста и плашек, смена объяснений, переходы экранов,
прокрутка перед переходом, бегущие строки, раскрытие шагов, подсказки снизу,
поворот стрелки, реакция иконок, модальные окна.

Исходная геометрия и движение
engine/assets содержит оригинальные SVG-контуры, параметры Laboratory,
скомпилированные треки и каталог SHA-256 исходников. Векторные контуры
тесселируются Lyon; мягкие свечения и маски кэшируются. Gallery и mirror
используют исходные растровые иллюстрации, их движение и шейдеры — Rust.
prepare-assets.mjs / css-motion.mjs / svg-dom.mjs — инструменты подготовки
ассетов, не JS-движок движения в продукте. Узлы треков 30 раз/с интерполируются
непрерывно в Rust; это не ограничение фактического рендера до 30 FPS.

Внешние ассеты
Крупные неизменяемые входы (растровые картины, длинные треки, кривые чтения)
не встраиваются в WASM: список — engine/assets/external.txt. Пример
publish_assets копирует их в public/graphics/pkg/assets под именами с хешем
содержимого. Страница загружает файлы сцены перед её созданием (имена называет
Rust: scene_assets/palette_assets), Rust проверяет длину и хеш каждого файла.
Нативный runtime (prepare-native.mjs) встраивает все файлы целиком.

Ключевые модули
engine/src/renderer.rs — общий wgpu device/queue, ресурсы, сцены и восстановление.
engine/src/vector_gpu.rs — геометрия, оригинальные paints, SVG-маски и фильтры.
engine/src/svg_motion.rs, tracks.rs, timeline.rs, motion.rs — движение и easing.
engine/src/voice.rs, gesture.rs, decoder.rs, cover_motion.rs — реакции и сценарии.
engine/src/element_motion.rs, panel_reveal.rs — презентация DOM-слоёв.
src/features/product/motion/rustEngine.web.ts — события и показ готового атласа.
src/features/product/motion/EffectsController.ts — один планировщик над navigator.

Плотность и плавность
Стекло и его фоновые текстуры: плотность 1,00 независимо от качества иллюстраций.
Иллюстрации: обычно 2,00–2,50. Аварийный минимум — 1,50.
Бюджет 384 000 пикселей мягкий: в обычном режиме он не опускает
иллюстрации ниже 2,00, в аварийном — ниже 1,50, стекло остаётся на 1,00.
Старт — стекло 1,00 / иллюстрации 2,00; цель — 90 FPS, доступны 60 и 120.
Плотность мягкого промежуточного blur может быть ниже; основная геометрия,
текст и основной выходной буфер от этого не получают меньшую плотность.
При устойчивой перегрузке: иллюстрации 2,50 → 2,00, затем три ступени
упрощения samples преломления/blur, частиц и второстепенного свечения.
Только сохраняющаяся перегрузка после них допускает 1,50 для иллюстраций.
При восстановлении сначала возвращается их чёткость, затем дорогие детали.
Исходные контуры и движение остаются; стекло сохраняет 1,00 на всех ступенях.
Контроллер использует rAF и реальную частоту готовых кадров эффектов.
JS-время вызова не выдаётся за время GPU. Оценка rAF не доказывает физическую
частоту панели. Порог снижения ~2 с, повышения ~18 с, пауза повышения ~20 с.
90 FPS — цель, не гарантия; аварийный минимум иллюстраций 1,50 сохраняется.

Ресурсы и пауза
Один GPU device, общие pipelines и атласы. Последний готовый кадр повторно
используется. Статическое стекло прекращает рисовать; blur обновляется только
при изменении источника/параметров. Геометрия не пересоздаётся от движения пальца.
Скрытая сцена приостанавливает свои часы. Размер, качество и возврат не меняют
фазу анимации. Потеря GPU восстанавливает CPU-состояние на новых ресурсах.
Browser adapter представляет регионы общего атласа через Canvas2D drawImage;
нет readPixels/getImageData или покадровой передачи больших массивов JS/WASM.
Стоимость этой операции представления ещё требует проверки на телефонах.

Сборка
PowerShell из корня проекта:
  .\graphics\product-engine\build.ps1 -Offline -ExportWeb
Необходимы Rust + wasm32-unknown-unknown и wasm-bindgen 0.2.129.
Если есть .local-rust, скрипт использует локальную цепочку инструментов.
-RefreshAssets обновляет ассеты из текущего Laboratory и генерирует шейдеры.
-Offline требует уже заполненного Cargo-кэша.
Скрипт запускает Rust-тесты, валидацию шейдеров, release WASM, bindgen,
TypeScript, lint и, с -ExportWeb, production export в .expo-rust-web-export.
Функциональные JS-тесты описаны в reports/RUST_GRAPHICS_2026-10-09.txt.

Просмотр и диагностика
  node graphics/product-engine/preview.cjs
Сервер: 127.0.0.1:8088, читает .expo-rust-web-export, поддерживает Brotli/gzip.
В настройках включается «Диагностика эффектов»: уровень, фактическая плотность,
основной/фоновый/blur буферы, готовые кадры, текстуры, причины переключения.
«Пересоздать графику» проверяет восстановление без сброса состояния.
?graphics-backend=webgl2 принудительно проверяет резервный backend.
?graphics=legacy — явный откат, ?graphics=rust-motion — промежуточный SVG-painter.
Обычный путь — полная Rust/wgpu-графика. Ошибочный fallback помечается причиной.
validation.html — отдельная техническая проверка тех же 16 сцен; это не экран
продукта и не результат проверки производительности на телефоне.

Платформы
Web: подключён к настоящим экранам, WebGPU и WebGL2 проверены.
Android: Art.native всё ещё использует прежний WebView, переходы — прежние
native wrappers. Нужны отдельный native surface/bridge, CNG-модуль/config plugin,
EAS-сборка и проверка на Tecno. Общие модели движения уже находятся в Rust,
но browser SVG/DOM adapter сам по себе не является Android-интеграцией.
