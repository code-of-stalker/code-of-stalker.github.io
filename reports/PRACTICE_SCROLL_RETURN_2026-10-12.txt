АРХИТЕКТУРА НАБЛЮДЕНИЯ: НИЖНИЙ КРАЙ И ВОЗВРАТ СКРОЛЛОМ
Дата: 12.10.2026

Уточнение точки возврата после проверки пользователем

Обратная прокрутка со второго шага теперь открывает последний вопрос
первого шага (4 из 4) и нижний край его содержимого. Выбор первого шага
в выпадающем списке по-прежнему открывает обзор. Ответы, completedAt
и availableAt сохраняются; повторное завершение не перезапускает таймер.
Остаток потока колеса после смены экрана не смещает точку возврата.
После нового жеста содержимое можно свободно прокручивать вверх.

Проверено в Chrome на 375 × 568: закрытый и открытый второй шаг,
реальное касание, повторный переход вперёд, возврат через вопросы
4 → 3 → 2 → 1, объяснения и обзор в выбор уровней, выбор шага из меню,
таймер из настроек. Использованы четыре зашифрованных тестовых ответа
на основе записи, сделанной через интерфейс приложения. Во всех четырёх
сценариях возврата scrollTop = 116 и максимальное смещение = 116.
Ошибок страницы нет. Линт, TypeScript, 14 проверок модели прокрутки
и веб-экспорт прошли. Публичная ссылка отдаёт актуальную сборку, HTTP 200.
Отчёт: .local-preview/panel-fixes/step-end-return-qa.json
Эти проверки браузерные; проверка нативного приложения на устройстве
в этом изменении не выполнялась.

Исправления

1. У прокручиваемого содержимого первого и второго шага, включая экран
   ожидания таймера, добавлено плавное затухание у нижнего края (24 px).
   В конце содержимого оставлено место, чтобы последний текст можно было
   полностью вывести из зоны затухания. Кнопка дневника остаётся чёткой.
2. Дополнительная прокрутка назад у верхнего края возвращает из второго
   шага в первый, а из первого — в выбор уровня. Обычное чтение до края
   само по себе не завершает переход. Для касания после достижения края
   учитывается только дальнейшее движение пальца.
3. Запрет перехода вперёд во втором шаге больше не блокирует возврат.
   Таймер, ответы и дата доступности сохраняются.
4. Под плашкой постоянно зарезервировано место для подсказки и прогресса
   жеста. Появление подсказки не меняет размеры плашки.
5. Один непрерывный поток колеса не может перескочить через оба экрана.
   История колеса сохраняется между сценами, используются временные
   метки входных событий, включая события, задержанные отрисовкой.
6. Открытый выбор шага и модальные окна блокируют жесты навигации.
   Возврат из тестового экрана таймера также открывает настоящий шаг 1,
   даже если ранее выбранным был шаг 2.

Проверки

- Expo lint: успешно, код завершения 0.
- TypeScript, tsc --noEmit: успешно, код завершения 0.
- Модель прокрутки: 14 тестов, все прошли.
- Веб-экспорт: успешно; файл Rust/WASM не изменялся.
- Chrome: все 6 групп сценариев прошли, ошибок страницы нет.
  В том числе проверены реальные события колеса, реальные касания через
  CDP, сохранение таймера, запрет перехода вперёд во втором шаге,
  закрытие навигации при открытом меню и прежний переход со сканированием.
- Chrome: 12 сочетаний темы и размера: тёмная, светлая, нейтральная;
  320x568, 375x568, 375x812, 768x1024. Последний текст можно прочитать
  полностью; кнопка и подсказка не перекрываются; горизонтального
  переполнения нет. Отдельно просмотрены снимки нижнего затухания
  и подсказки возврата.
- Длинный поток колеса с исходными временными метками событий:
  один переход после смены сцены; новый жест выполняет следующий возврат.
- Публичная ссылка: HTTP 200, HTML подключает текущую сборку,
  файл сборки доступен с HTTP 200.

Ограничение проверки Safari

Автоматический WebKit на этом компьютере остановился при запуске
графического Rust/WASM движка на экране настроек, до начала сценариев:
RuntimeError: Unreachable code should not be executed.
Повтор с принудительным WebGL2 и запуск с обычным выбором графики дали
тот же результат. Проверка текущих исправлений в WebKit не подтверждена.
Настоящие устройства Android/iOS в этой задаче не проверялись.
