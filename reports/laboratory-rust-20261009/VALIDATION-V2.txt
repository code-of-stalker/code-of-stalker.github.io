Laboratory Rust glass — moving-scene workload v2 — 2026-10-09

CORRECTION AFTER TECNO FEEDBACK
The user reported that Observer did not play in either engine. Investigation found
that a new dangerouslySetInnerHTML object on each React render replaced the SVG when
metrics updated, restarting its animation about every 700ms. Prior render and pause
checks did not validate sustained motion. The v2 benchmark is not proof of full SVG
animation load. Fixed in v3 with stable SVG content and live transform/node monitoring.
Keep the records below as historical checks; use VALIDATION-V3.txt for the correction.

Scope delivered
- Default scene: original Laboratory Matrix rain behind the glass, with the existing
  AttentionAwareness SVG animation (Наблюдающий) inside the panel.
- Three selectable workloads: static glass, glass + rain, glass + rain + Observer.
- Same Canvas2D rain implementation, deterministic seed/preset, SVG, geometry and
  density for the Three.js reference and Rust renderer. Default/max density: 2.
- Rain updates at up to 30 fps. Both engines upload newly painted source frames and
  invalidate their two-pass background blur. Rust uses the external-canvas copy API;
  no per-frame getImageData readback was introduced.
- Only one glass engine is alive at a time. Pause and hidden-tab handling also pause
  the SVG. Measurement restarts the scene and records the workload and rain update rate.
- Export schemaVersion 2, benchmark rain-observer-v2, file laboratory-rust-comparison-v2.json.
- Rain and SVG were reused as browser components, not rewritten in Rust. This is a
  comparison of the glass engines under the same additional scene load.
