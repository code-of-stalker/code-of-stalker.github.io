Laboratory Rust comparison — Observer playback correction — 2026-10-09

Reported defect and reproduced cause
- User: Observer remained still in both v2 engine modes on Tecno.
- The component created a new dangerouslySetInnerHTML object on every React render.
  Installed React DOM 19.2.3 sets innerHTML again when that object identity changes.
  The benchmark publishes metrics every 700ms, replacing the SVG and resetting its
  CSS animations before the camera's initial 2.24-second hold could end.
- Before the correction the browser reported animation-play-state running but camera
  matrix(3.2, 0, 0, 3.2, -352, -6.4), dash offset 0 and ray opacity 0 repeatedly.
  A requested playing flag and successful renderer initialization were insufficient QA.

Correction
- Memoize the SVG innerHTML object in the experiment's AttentionAwareness copy.
- Memoize the Observer component at the benchmark boundary, so metric updates do not
  rerender it. The memoized HTML also preserves nodes on pause/resume and prop changes.
- Explicit replay still replaces the animation root once, as intended.
- Original SVG artwork and its animation timing are unchanged.
- Added a low-frequency probe of actual camera transforms and DOM node continuity.
  A running flag alone, a static transform, or repeated node replacement cannot pass.
- Visible Observer status and each saved benchmark row include playback evidence.
- Measurement starts above the scene and scrolls it into the viewport. An intersection
  guard cancels the measurement if less than 80% of the scene remains visible. This
  prevents offscreen rendering optimizations from silently reducing the tested load.
- New export: schemaVersion 3, benchmark rain-observer-v3, laboratory-rust-comparison-v3.json.
